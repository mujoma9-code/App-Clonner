# Clonner for iOS

A SwiftUI launcher plus a DNS ad-blocking profile. **It does not clone apps**, and this
file explains why that is not a missing feature.

## Why there is no cloning here

iOS has no mechanism for it, and no signing arrangement unlocks one:

| What cloning needs | iOS |
|---|---|
| List the installed apps | No API exists. `canOpenURL` only answers for schemes declared up front, capped at 50. |
| Launch another app | Only through URL schemes that app chose to publish. |
| Place a home-screen icon | No API. Safari (web pages) and the Shortcuts app only. |
| Duplicate a binary or its container | The sandbox forbids it outright. |

**Sideloading does not change this.** A signer gets an app *installed*; it does not grant
entitlements. An app installed through AltStore, Sideloadly or ESign runs in exactly the
same sandbox as one from the App Store. Only a jailbreak or a TrollStore-style install with
private entitlements changes the picture, and neither is something this project targets.

## What it does instead

- **Clones tab** — a curated catalogue of 50 well-known apps, probed with `canOpenURL` to
  show only what you actually have. Give each one your own name and colour.
- **Home-screen icons** — through the Shortcuts app, the supported route. The app hands you
  a `clonner://open?id=<uuid>` deep link and walks you through the five steps. You get to
  pick any photo as the icon, which is more than the Android side can offer.
- **Shield tab** — installs the DNS configuration profile. Not a Network Extension:
  `NEDNSSettingsManager` needs the `com.apple.developer.networking.networkextension`
  entitlement, which personal signing certificates do not carry. A configuration profile
  needs no entitlement, no extension and no App Store review.

## The ad blocker works on its own

`Clonner-AdShield-AdGuard.mobileconfig` needs no app at all. AirDrop or email it to the
phone, tap it, then **Settings → General → VPN & Device Management** and install. It points
DNS at AdGuard's filtering resolver over encrypted HTTPS, so ad lookups fail device-wide.

Verified against the live resolver: `doubleclick.net`, `pagead2.googlesyndication.com`,
`tpc.googlesyndication.com`, `ads.mopub.com` and `app-measurement.com` all return the
`0.0.0.0` sinkhole, while `apple.com`, `icloud.com` and `github.com` resolve normally.

Remove it the same way to turn it off. It is a plain, readable XML plist — worth opening in
a text editor before you install it.

DNS filtering blocks the *request* that fetches an ad. It cannot remove ad space already
laid out inside an app, and it will not stop ads served from the same domain as the app's
real content — YouTube's in-video ads being the well-known case.

## Building

The project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from
`project.yml`, so there is no `.xcodeproj` in the repo.

```bash
brew install xcodegen
cd ios
xcodegen generate --spec project.yml
open Clonner.xcodeproj
```

`objectVersion: 56` is pinned deliberately: current XcodeGen defaults to format 77, which
only Xcode 16+ can open, and pinning keeps the project readable across Xcode 14–16.

### Getting an IPA without a Mac

`.github/workflows/ios-build.yml` builds on a GitHub-hosted macOS runner and uploads an
**unsigned** `.ipa`. Push to the branch, or run the workflow manually from the Actions tab,
then download `Clonner-unsigned-ipa` from the run's Artifacts section and re-sign it with
your own signer before installing.

The catalogue and `LSApplicationQueriesSchemes` must stay exactly 1:1 — an entry missing
from the plist silently reports as "not installed" forever. There is a check for this:

```bash
python3 - <<'PY'
import re, yaml
declared = set(yaml.safe_load(open('ios/project.yml'))
               ['targets']['Clonner']['info']['properties']['LSApplicationQueriesSchemes'])
used = set(re.findall(r'scheme:\s*"([^"]+)"', open('ios/Clonner/Model/AppCatalog.swift').read()))
print("missing from plist:", sorted(used - declared) or "none")
print("unused slots:", sorted(declared - used) or "none")
PY
```
